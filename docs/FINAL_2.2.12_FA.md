# نسخهٔ نهایی ۲.۲.۱۲ — ویرایش کامل پیام استارت از پنل

این نسخه تجمیعی است و روی ۲.۲.۱۱ ساخته شده؛ تغییرات قبلی حذف نشده‌اند:

- بدون سقف ثابت CPU/RAM برای ربات در تنظیمات Compose؛ بهینه‌سازی‌های منابع و ffmpeg حفظ شده‌اند.
- خرید و تسویهٔ اتمیک، کسر مبلغ فقط یک‌بار، مصرف خدمت ثبت‌شده و عودت ماندهٔ استفاده‌نشده.
- گزارش شروع پیش از ورود اکانت‌ها و گزارش نهایی پس از وضعیت نهایی؛ جلوگیری از تلاش‌های تکراری و شروع معوق.
- اصلاحات منو، دکمه‌ها، حالت تعمیرات، نمایندگی‌ها و لایهٔ ایموجی پریمیوم.
- متن سفارشی قدیمی و متغیرهای `{name}` و `{credit}` همچنان کار می‌کنند.

## تمام بخش‌های پیام، قابل تنظیم

مسیر با حساب سوپرادمین:

**پنل مدیریت → تنظیمات → 📝 تنظیم متن استارت**

| دکمه | کاربرد |
|---|---|
| 🏷 نام برند | نام برند؛ پیش‌فرض نام نمایشی همین ربات |
| 💬 شعار برند | شعار کوتاه معرفی |
| 📝 متن معرفی | توضیح اصلی خدمات |
| ✨ ویژگی‌های خدمات | مزیت‌های واقعی خدمات، هر مورد در یک خط |
| 🧭 راهنمای خرید | مراحل خرید و پیگیری |
| 🚀 دعوت به شروع | جملهٔ پایانی پیام |
| 🎙 عنوان سرویس ویس | عنوان نمایشی سرویس ویس |
| 👥 عنوان سرویس گروه | عنوان نمایشی عضویت گروه |
| 📢 عنوان سرویس کانال | عنوان نمایشی عضویت کانال |
| 💬 عنوان سرویس چت ویس | عنوان نمایشی چت در ویس |
| 📞 راه ارتباطی پشتیبانی | آیدی یا توضیح مسیر پشتیبانی |
| 🕒 ساعت پاسخ‌گویی | ساعت واقعی پاسخ‌گویی |

هر بخش مقدار فعلی، بازگشت بدون ذخیره و دکمهٔ **«↩️ پیش‌فرض این بخش»** دارد. تغییر عنوان یک سرویس، خودِ سرویس را فعال نمی‌کند؛ فعال/غیرفعال کردن از مدیریت سرویس‌هاست. `{services}` فقط سرویس‌های فعال همان ربات را نشان می‌دهد.

متن کامل، تیترها، ترتیب بخش‌ها، فاصله‌ها و ایموجی‌ها نیز با ارسال قالب سفارشی در همین صفحه قابل تغییرند. برای اثر کردن تغییر یک پارامتر، متغیرش باید در قالب باشد. نام و موجودی واقعی کاربر خودکارند؛ این ویرایشگر برای تغییر موجودی یا جعل اطلاعات حساب نیست.

### پیش‌نمایش و فعال‌سازی

1. **«🔎 پیش‌نمایش قالب پیشنهادی»** را بزنید؛ طرح جدید با پارامترهای فعلی و اطلاعات حساب ادمین نمایش داده می‌شود، بدون ذخیره یا ارسال برای مشتریان.
2. برای فعال کردن، **«✨ قالب پیشنهادی»** را بزنید؛ قالب جدید ذخیره می‌شود ولی پارامترهای برند/پشتیبانی قبلی را پاک نمی‌کند.
3. بخش‌های دلخواه را با دکمه‌های بالا تنظیم کنید؛ هر ذخیره پیش‌نمایش دارد.
4. **«👁 پیش‌نمایش استارت»** متن فعلی ذخیره‌شده را نشان می‌دهد.
5. **«📄 متن قالب فعلی»** متن خام را برای کپی و ویرایش می‌فرستد.

**آپدیت به‌تنهایی متن سفارشی قبلی را جایگزین نمی‌کند.** اگر هنوز راهنمای کوتاه قدیمی «متن استارت ({name}, {credit})» را می‌بینید، ابتدا نسخهٔ در حال اجرای ربات را بررسی کنید؛ راهنمای نسخهٔ جدید تمام متغیرها و دکمه‌های بالا را دارد.

## قالب پیشنهادی نهایی

همین قالب داخل ربات آماده است؛ لازم نیست دستی واردش کنید:

```html
👋 <b>{name} عزیز، خوش آمدید!</b>

💎 <b>{brand}</b>
<i>{tagline}</i>

{intro}
━━━━━━━━━━━━━━
🎯 <b>خدمات در دسترس شما</b>
{services}

💳 <b>کیف پول شما</b>
موجودی: <code>{credit}</code> تومان
شناسه کاربری: <code>{id}</code>
━━━━━━━━━━━━━━
✨ <b>با آگاهی انتخاب کنید</b>
{benefits}

🚀 <b>شروع، در سه قدم</b>
{guide}

📞 <b>کنار شما هستیم</b>
{support}
🕒 {support_hours}

👇 <b>{cta}</b>
```

مقادیر آمادهٔ متن:

- **شعار:** انتخاب آسان، هزینه روشن، پیگیری سفارش در یک‌جا
- **معرفی:** برای حضوری پررنگ‌تر در تلگرام، سرویس مناسب خودتان را انتخاب کنید؛ از ثبت تا پیگیری سفارش، همراه شما هستیم.
- **ویژگی‌ها:** بررسی جزئیات و مبلغ پیش از تأیید خرید؛ دسترسی به وضعیت و سوابق سفارش‌ها؛ ارتباط با پشتیبانی از داخل ربات.
- **راهنما:** انتخاب پلن از خرید سرویس؛ بررسی جزئیات و مبلغ و تأیید؛ پیگیری از سفارشات من.
- **دعوت به شروع:** انتخاب شما، قدم بعدی است؛ از منوی پایین شروع کنید.

نام برند و ساعت واقعی پشتیبانی را خودتان تنظیم کنید. متن آماده وعدهٔ امنیت مطلق، ممبر واقعی یا پشتیبانی ۲۴ ساعته نمی‌دهد.

متغیرهای دیگر: `{first_name}`، `{full_name}`، `{username}`، `{bot_name}`، `{bot_username}`، `{date}` و `{time}`. نام‌های کاربری بدون @، تاریخ شمسی و ساعت تهران‌اند. موجودی با اعشار حفظ می‌شود. [راهنمای پایهٔ متغیرها](START_MESSAGE_2.2.11_FA.md)

## اعتبارسنجی و سازگاری

- قالب تا ۲۵۰۰ نویسه؛ معرفی ۲۴۰، ویژگی‌ها و راهنما هرکدام ۳۶۰، سایر پارامترها ۱۲۰ نویسه.
- متغیرها متن ساده و escape‌شده‌اند؛ HTML یا متغیر داخل نام کاربر دوباره تفسیر نمی‌شود.
- اگر بسط قالب از بودجهٔ امن پیام عبور کند، طرح استاندارد و در صورت لزوم طرح فشرده با حفظ موجودی نمایش داده می‌شود؛ متن ذخیره‌شده پاک نمی‌شود.
- تنظیمات نمایندگی‌ها مستقل‌اند و تنظیمات استارت با یک query خوانده می‌شوند.
- نمایش پریمیوم تابع تنظیمات و مجوز تلگرام است؛ fallback معمولی حفظ شده است.
- migration جدید لازم نیست؛ از جدول تنظیمات موجود استفاده می‌شود.

## بررسی نسخه

**۳۵۵ تست موفق بدون skip، شامل ۳۱ تست PostgreSQL واقعی**؛ ۱۲ تست جدید برای بخش‌های جدید، عنوان سرویس غیرفعال، متن خام، پیش‌نمایش بدون تغییر تنظیمات، reset، بازگشت، اندازهٔ پیام و ذخیرهٔ مستقل نمایندگی. compileall و diff-check نیز اجرا شدند. API تلگرام mock است؛ تست زنده یا نصب روی سرور مشتری انجام نشده است.

## دستورات نصب امن

**پیش از نصب:** تعمیرات را روشن کنید؛ اجازه دهید سفارش‌های فعال تمام شوند؛ از دیتابیس، `.env` و داده‌های پروژه بکاپ بگیرید. اتصال سفارش بعد از restart خودکار ادامه نمی‌یابد؛ سفارش قطع‌شده از روی checkpoint تسویه می‌شود. این نسخه آن محدودیت را تغییر نداده است.

در پوشهٔ واقعی پروژه، برای Compose موجود می‌توانید بکاپ دیتابیس بگیرید (فایل را خارج از همین سرور هم نگه دارید):

```bash
(
set -e
umask 077
mkdir -p backups
stamp=$(date +%Y%m%d-%H%M%S)
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > "backups/before-2.2.12-$stamp.dump"
test -s "backups/before-2.2.12-$stamp.dump"
if [ -f .env ]; then cp -p .env "backups/env-before-2.2.12-$stamp"; fi
)
```

فقط بعد از موفقیت بکاپ، نصب را اجرا کنید:

```bash
(
set -e
if [ -n "$(git status --porcelain)" ]; then
  echo 'Local changes exist; preserve and review them before updating.'
  exit 1
fi
git fetch origin
git switch arena/01a0b5c9-tgcallbot
git pull --ff-only origin arena/01a0b5c9-tgcallbot
docker compose up -d --build --no-deps bot
docker compose logs --tail=120 bot
)
```

در لاگ/پنل، نسخهٔ **2.2.12** را بررسی کنید. سپس قالب پیشنهادی را از پنل فعال کنید، نام برند و پشتیبانی را تنظیم کنید، `/start` را تست و تعمیرات را خاموش کنید.

بررسی سقف منابع در سطح تنظیمات کانتینر:

```bash
docker inspect "$(docker compose ps -q bot)" --format 'Memory={{.HostConfig.Memory}} NanoCpus={{.HostConfig.NanoCpus}} CpuQuota={{.HostConfig.CpuQuota}}'
```

مقادیر صفر یعنی سقف صریح این فیلدها روی کانتینر تنظیم نشده؛ محدودیت احتمالی هاست/والد جداست. از `docker compose down -v`، `git reset --hard` و حذف داده‌ها استفاده نکنید. در صورت خطای هر مرحله، ادامه ندهید.
