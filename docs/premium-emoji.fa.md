# 💎 ایموجی پریمیوم (Custom Emoji) در ربات

این سند قابلیت «ایموجی پریمیوم» را توضیح می‌دهد: اینکه چه چیزی خودکار
ارتقا پیدا می‌کند، چه چیزی پیدا نمی‌کند، چطور روشن/خاموش و سفارشی می‌شود،
و اگر ایموجی پریمیوم ندیدید از کجا عیب‌یابی کنید.

> نسخهٔ لازم: **Bot API 9.4 (۹ فوریهٔ ۲۰۲۶)** به بعد و
> **python-telegram-bot ≥ 22.8** (فیلد `icon_custom_emoji_id` روی دکمه‌ها).

---

## ۱) پیش‌نیاز اصلی: پریمیوم روی اکانتِ «مالکِ ربات»

تا قبل از Bot API 9.4، ربات فقط با خرید یوزرنیمِ کلکسیونی در Fragment
(چند هزار TON) می‌توانست ایموجی سفارشی بفرستد. از **۹ فوریهٔ ۲۰۲۶** قانون
عوض شد:

> Allowed bots to use custom emoji in messages directly sent by the bot to
> **private, group and supergroup** chats if the **owner of the bot** has a
> Telegram Premium subscription.

یعنی:

| شرط | توضیح |
|---|---|
| اشتراک **Telegram Premium** | روی همان اکانتی که ربات را در **BotFather** ساخته است (نه روی اکانت‌های ویس‌کال ربات) |
| نوع چت | **خصوصی، گروه، سوپرگروه** — در **کانال** ایموجی سفارشی مجاز نیست |
| شناسهٔ ایموجی | `custom_emoji_id` (شناسهٔ سندِ استیکرِ ایموجی) باید معتبر باشد |

اگر مالک پریمیوم نداشته باشد، تلگرام یا ایموجی یونیکدِ جایگزین را نشان
می‌دهد یا خطا می‌دهد؛ در **هر دو حالت** این لایه به‌صورت خودکار پیام را
بدون ایموجی پریمیوم ارسال می‌کند (fallback)، پس هیچ پیامی از دست نمی‌رود.

---

## ۲) چه چیزهایی خودکار ارتقا پیدا می‌کنند؟

همه‌چیز از **یک نقطه** انجام می‌شود: کلاس‌های `PremiumEmojiBot` و
`PremiumEmojiApplication` در [`utils/premium_bot.py`](../utils/premium_bot.py).
چون در PTB همهٔ مسیرهای ارسال (`context.bot.send_message`،
`message.reply_text`، `callback_query.edit_message_text`، `send_safe` و …)
در نهایت به متدهای خودِ `Bot` می‌رسند، **هیچ هندلری لازم نبود تغییر کند**.

| خروجی | رفتار |
|---|---|
| متن پیام با `parse_mode=HTML` | ایموجی‌های یونیکد به `<tg-emoji emoji-id="…">✅</tg-emoji>` تبدیل می‌شوند (داخل `<code>`/`<pre>` و تگ‌های `<tg-emoji>` موجود دست نمی‌خورد) |
| متن پیام **بدون** parse_mode | متن دست‌نخورده می‌ماند و entity از نوع `custom_emoji` اضافه می‌شود (مطمئن‌ترین روش؛ آفست‌ها بر حسب UTF-16 محاسبه می‌شوند) |
| متن پیام با `parse_mode=Markdown` | به HTML تبدیل می‌شود (`**بولد**` → `<b>بولد</b>`) و سپس ایموجی پریمیوم می‌گیرد |
| متنِ حاوی `pe("rocket")` بدون parse_mode | خودکار به HTML معتبر تبدیل می‌شود (بقیهٔ متن escape می‌شود) |
| کپشن عکس/ویدئو/فایل/ویس | مثل متن پیام |
| آلبوم (`send_media_group`) | کپشن هر `InputMedia` جداگانه |
| **دکمه‌های inline** | ایموجیِ اول/آخرِ متن دکمه به `icon_custom_emoji_id` تبدیل و از متن حذف می‌شود |
| **دکمه‌های کیبورد اصلی (reply)** | همین‌طور، به‌علاوهٔ «لایهٔ بازگردانی برچسب» (بند ۴) |
| پیام‌های ورودی کاربر/ادمین | اگر خودش ایموجی پریمیوم فرستاده باشد، با `text_html` **دقیقاً همان** بازنشر می‌شود |

### کجاها عمداً ارتقا نمی‌یابد؟

- **کانال‌ها** (لاگ، گزارش مالی، بکاپ): طبق Bot API 9.4 ایموجی سفارشی در
  کانال مجاز نیست. نوع چت در حافظه کش می‌شود و کانال‌ها بدون حتی یک تلاش
  رد می‌شوند (`PREMIUM_EMOJI_SKIP_CHANNELS=true`).
- **`answerCallbackQuery`** (toast/pop-up دکمه‌ها): این متد entity و HTML
  نمی‌پذیرد، پس ایموجی یونیکد می‌ماند.
- **`setMyCommands`** (فهرست دستورات ربات): پشتیبانی نمی‌شود.
- **`copy_message` / `message.copy()`** (پیام همگانی و پیام خصوصی ادمین):
  خودِ تلگرام همهٔ entityها از جمله ایموجی پریمیومِ ادمین را عیناً منتقل
  می‌کند؛ نیازی به دخالت ما نیست.
- **چت داخل ویس‌کال (Pyrogram/MTProto)**: آن پیام‌ها از طرف «اکانت کاربر»
  ارسال می‌شوند نه ربات؛ ایموجی سفارشی در آن مسیر به پریمیوم بودنِ خودِ
  اکانت بستگی دارد و از این قابلیت جداست.

## ۳) بستهٔ ایموجی و شناسه‌ها

بستهٔ آماده در [`utils/premium_emoji.py`](../utils/premium_emoji.py) است:

```python
PREMIUM_EMOJI_PACK = OrderedDict([
    ("check",  ("5805532930662996322", "✅")),
    ("cross",  ("5210952531676504517", "❌")),
    ("rocket", ("5389102131527556772", "🚀")),
    ...
])
```

هر ورودی = `کلید معنایی → (شناسهٔ ایموجی پریمیوم، ایموجی یونیکدِ جایگزین)`.
همچنین یک نگاشت بزرگِ «یونیکد → شناسه» ساخته می‌شود (با و بدون
Variation Selector)، به‌همراه چندصد معادلِ دستی (`☎️→📞`، `🟢→✅`، …) تا
همان ایموجی‌هایی که **همین حالا** در منوها و متن‌های ربات هست ارتقا یابد.

برای دیدن فهرست کامل:

```bash
python tools/premium_emoji_sync.py --list
```

### اعتبارسنجی خودکار در هر استارت

در بالا آمدنِ ربات (`services/premium_emoji_service.initialize`) همهٔ
شناسه‌ها با متد رسمی `getCustomEmojiStickers` سنجیده می‌شوند (هر ۲۰۰ شناسه
یک فراخوانی). شناسهٔ نامعتبر **خودکار** از مدار خارج می‌شود و ایموجی
یونیکد جای آن را می‌گیرد؛ فهرست نامعتبرها هم در دیتابیس ذخیره می‌شود تا
استارت‌های بعدی سریع‌تر باشند. اگر API خطا بدهد یا هیچ شناسه‌ای تایید نشود،
اعتبارسنجی «انجام‌نشده» فرض می‌شود و **هیچ شناسه‌ای غیرفعال نمی‌شود** (تا یک
خطای گذرا کل قابلیت را خاموش نکند).

### کنترلِ «ایموجیِ نامربوط»

پاسخِ `getCustomEmojiStickers` فیلد `Sticker.emoji` را هم برمی‌گرداند؛ لایهٔ
اعتبارسنجی آن را با ایموجیِ مورد انتظارِ بسته مقایسه می‌کند. اگر شناسه‌ای
معتبر باشد ولی شکلِ دیگری داشته باشد (مثلاً به‌جای ✅ یک 🧊 نشان دهد)، در
لاگ و در پنل ادمین **گزارش** می‌شود تا بتوانید شناسهٔ درست را با «🔧
جایگزینی شناسه» بگذارید. با `PREMIUM_EMOJI_STRICT_MATCH=true` همان شناسه‌ها
خودکار غیرفعال هم می‌شوند (پیش‌فرض: خاموش، چون بعضی پک‌ها عمداً شکلِ
متفاوتی برای یک ایموجی دارند).

### پوششِ ایموجی‌های موجود در مخزن

با اسکن کامل کد، **۲۱۹** ایموجی یونیکدِ به‌کاررفته در متن‌های ربات نگاشتِ
«یونیکد → شناسه» دارند. آنچه عمداً بدون نگاشت مانده فقط این‌هاست:

* پیکان‌های تایپی (`→` `←` `⇒`) — ایموجی نیستند.
* حروف سازندهٔ پرچم (`🇮🇷`) و اجزای توالی‌های ZWJ/keycap (`♂` `⃣`) — تبدیلشان
  پرچم/عدد را می‌شکند.
* ایموجی‌های `QUICK_REACTIONS` در `handlers/incall_handlers.py` — این‌ها
  **ری‌اکشنِ داخل ویس‌کال** از طرف اکانت کاربر (MTProto) فرستاده می‌شوند نه
  از طرف ربات، پس از این لایه عبور نمی‌کنند.

## ۴) چرا دکمه‌های کیبورد اصلی نمی‌شکنند؟

آیکونِ دکمه (`icon_custom_emoji_id`) **قبل از** متن نمایش داده می‌شود؛ پس
برای جلوگیری از «دو ایموجی شدن»، ایموجی از متن دکمه حذف می‌شود.

- در دکمه‌های **inline** این کار کاملاً امن است، چون تطبیق دکمه همیشه با
  `callback_data` یا `url` انجام می‌شود نه با متن.
- در دکمه‌های **reply** متنِ دکمه همان چیزی است که کاربر می‌فرستد و این
  ربات ده‌ها فیلتر دقیق مثل `filters.Regex("^🆘 پشتیبانی$")` دارد.

راه‌حل: هر برچسبی که ایموجی‌اش حذف می‌شود در یک
`OrderedDict` (با سقف ۴۰۰ مورد) ثبت می‌گردد:

```
"پشتیبانی"  →  "🆘 پشتیبانی"
```

و `PremiumEmojiApplication.process_update` **پیش از** dispatch هر آپدیت،
اگر متنِ دریافتی دقیقاً یکی از این برچسب‌ها باشد، متنِ اصلی (با ایموجی)
بازگردانده می‌شود و آفست entityها هم به همان اندازه جابه‌جا می‌گردد.
نتیجه: تمام هندلرها، فیلترها و `ConversationHandler`ها **بدون هیچ تغییری**
دقیقاً مثل قبل کار می‌کنند.

اگر ترجیح می‌دهید ریسکِ صفر باشد:
`PREMIUM_EMOJI_REPLY_BUTTONS=false` (یا کلید «آیکون کیبورد اصلی» در پنل
ادمین) — آن‌وقت دکمه‌های کیبورد اصلی همان ایموجی یونیکد را نگه می‌دارند.

## ۵) تنظیمات

### ۵.۱) فایل `.env`

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PREMIUM_EMOJI_ENABLED` | `true` | کلید اصلیِ قابلیت |
| `PREMIUM_EMOJI_TEXT` | `true` | ایموجی پریمیوم در متن پیام‌ها/کپشن‌ها |
| `PREMIUM_EMOJI_BUTTONS` | `true` | آیکون پریمیوم روی دکمه‌های inline |
| `PREMIUM_EMOJI_REPLY_BUTTONS` | `true` | آیکون پریمیوم روی دکمه‌های کیبورد اصلی |
| `PREMIUM_EMOJI_TRAILING_ICONS` | `true` | ایموجیِ انتهای متن دکمه هم به آیکون تبدیل شود |
| `PREMIUM_EMOJI_MARKDOWN_TO_HTML` | `true` | تبدیل پیام‌های Markdown به HTML |
| `PREMIUM_EMOJI_VALIDATE` | `true` | اعتبارسنجی شناسه‌ها در استارت |
| `PREMIUM_EMOJI_SKIP_CHANNELS` | `true` | رد کردن کانال‌ها بدون تلاش |
| `PREMIUM_EMOJI_MAX_PER_MESSAGE` | `90` | سقف ایموجی در هر پیام (تلگرام حداکثر ۱۰۰ entity) |
| `PREMIUM_EMOJI_STRICT_MATCH` | `false` | اگر `true` باشد شناسه‌ای که ایموجیِ واقعی‌اش با بسته نمی‌خواند هم غیرفعال می‌شود (پیش‌فرض: فقط گزارش) |
| `PREMIUM_EMOJI_OVERRIDES` | *(خالی)* | جایگزینی شناسه‌ها با JSON یا `key=id,key=id` |

### ۵.۲) پنل ادمین

```
🔐 پنل مدیریت (ادمین) → ⚙️ تنظیمات سیستم → 💎 ایموجی پریمیوم
```

* چهار کلید روشن/خاموش (ذخیره در دیتابیس؛ پس از ری‌استارت می‌ماند و بر
  `.env` اولویت دارد)
* «🧪 پیام تست» — یک پیام نمونه با ایموجی پریمیوم + دکمه‌های inline و
  یک کیبورد reply با آیکون پریمیوم
* «📋 پیش‌نمایش بسته» — همهٔ کلیدها با ایموجی واقعی و وضعیت اعتبار
* «🔄 اعتبارسنجی شناسه‌ها» — اجرای دستیِ `getCustomEmojiStickers`
* «🔧 جایگزینی شناسه» — override با قالب `rocket=5389102131527556772`
  یا `🚀=5389102131527556772` یا JSON کامل (چند خط یک‌جا هم می‌شود)
* «🛜 کشف از اکانت (MTProto)» — خواندن پک‌های عمومیِ ایموجی پریمیوم با
  یکی از اکانت‌های فعال ربات و جایگزینی خودکار شناسه‌ها

## ۶) استفاده در کد (متن‌های جدید)

برای متن‌هایی که از اول با HTML نوشته می‌شوند نیازی به کار خاصی نیست —
ایموجی یونیکدِ معمولی بنویسید، لایهٔ خروجی خودش ارتقا می‌دهد. اگر می‌خواهید
صریح باشید:

```python
from utils.premium_emoji import pe

text = f"{pe('gem')} <b>پنل مدیریت</b>\n{pe('check')} سفارش فعال شد"
await context.bot.send_message(chat_id, text, parse_mode=ParseMode.HTML)
```

`pe()` هم با **کلید معنایی** کار می‌کند (`pe("rocket")`) هم با **ایموجی
یونیکد** (`pe("🚀")`) و اگر قابلیت خاموش باشد یا شناسه معتبر نباشد، همان
ایموجی یونیکد را برمی‌گرداند — پس استفاده از آن در هر parse_mode ای امن است.

### بازنشرِ ایموجی پریمیومِ خودِ کاربر

```python
from utils.premium_emoji import message_content_html

html_text = message_content_html(update.message)   # text_html / caption_html
await context.bot.send_message(admin_id, f"💬 {html_text}", parse_mode="HTML")
```

`text_html` خودِ PTB همهٔ entityها از جمله `custom_emoji` را به تگ
`<tg-emoji>` تبدیل می‌کند و متن را هم escape می‌نماید. این دقیقاً همان چیزی
است که در مسیر تیکت استفاده شده است:

* پیام کاربر → ادمین: `handlers/ticket_handlers.py::_persist_user_message`
* پاسخ ادمین → کاربر: `handlers/ticket_handlers.py::handle_admin_reply_message`
* پیام همگانی و پیام خصوصی: `copy_message` / `message.copy()` (انتقالِ بومیِ
  entityها توسط خود تلگرام)

## ۷) ابزار خط فرمان

```bash
# فهرست بستهٔ ایموجی
python tools/premium_emoji_sync.py --list

# اعتبارسنجی همهٔ شناسه‌ها با توکن ربات
python tools/premium_emoji_sync.py --validate --token "$BOT_TOKEN"

# همین + چاپ یک خط آماده برای .env
python tools/premium_emoji_sync.py --validate --token "$BOT_TOKEN" --env --json data/premium_emoji.json

# کشف شناسه از یک پک پریمیوم با اکانت MTProto (بدون نیاز به دیتابیس)
python tools/premium_emoji_sync.py --discover NewsEmoji,TgAndroidIcons \
    --api-id 1234 --api-hash XXXX --session-string "..." --env
```

## ۸) شناسهٔ ایموجی دلخواه را از کجا پیدا کنیم؟

1. **پنل ادمین → «🛜 کشف از اکانت»**: راحت‌ترین راه داخل خودِ ربات.
2. **ابزار خط فرمان** (`--discover`) روی لپ‌تاپ.
3. **Telegram Web**: در `web.telegram.org` یک پیام حاوی ایموجی پریمیوم را
   Inspect کنید؛ فیلد `customEmojiId` را می‌بینید.
4. **ربات‌های استخراج‌کنندهٔ شناسه**: ایموجی پریمیوم را برای آن‌ها
   بفرستید تا `custom_emoji_id` را بدهند.
5. از یک پیامِ موجود: اگر کاربری ایموجی پریمیوم بفرستد، در آپدیتِ
   `entities` مقدار `custom_emoji_id` هست (ربات همین را برای بازنشر استفاده
   می‌کند).

## ۹) عیب‌یابی

| نشانه | علت احتمالی | راه‌حل |
|---|---|---|
| همه‌جا ایموجی معمولی است | مالکِ ربات پریمیوم ندارد | روی اکانتِ سازندهٔ ربات در BotFather اشتراک Premium بگیرید |
| فقط در کانال معمولی است | محدودیت Bot API | طبیعی است؛ ایموجی سفارشی در کانال مجاز نیست |
| در لاگ: `chat … custom emoji را نپذیرفت` | چت/ربات مجاز نبوده | طبیعی؛ آن چت از فهرست ارتقا خارج شد و پیام سالم رفت |
| `Can't parse entities` | شناسهٔ نامعتبر یا تگِ nested | «اعتبارسنجی شناسه‌ها» را در پنل ادمین بزنید |
| دکمه‌های کیبورد اصلی کار نمی‌کنند | لایهٔ بازگردانی برچسب غیرفعال شده | `PREMIUM_EMOJI_REPLY_BUTTONS=false` بگذارید و ربات را ری‌استارت کنید |
| `icon_custom_emoji_id` ناشناخته | نسخهٔ قدیمی PTB | `pip install -U "python-telegram-bot[job-queue]"` (≥ 22.8) |
| متن Markdown به‌هم ریخت | تبدیل Markdown→HTML | `PREMIUM_EMOJI_MARKDOWN_TO_HTML=false` |

برای دیدن وضعیت زندهٔ قابلیت (تعداد پیام‌های ارتقایافته، fallbackها،
شناسه‌های معتبر/نامعتبر) به پنل ادمین → «💎 ایموجی پریمیوم» بروید یا لاگ
استارت را ببینید:

```
premium-emoji: premium_emoji=ON[TBR] ids=131/131 overrides=0 validated=True stats={...}
```

### نکات ایمنی که در طراحی رعایت شده

* **هرگز پیامی از دست نمی‌رود**: اگر تلگرام payload ارتقایافته را نپذیرد،
  بلافاصله همان پیام با payload اصلی ارسال می‌شود.
* **سقف entity**: حداکثر ۹۰ ایموجی در هر پیام (تلگرام ۱۰۰ entity
  می‌پذیرد و جای بولد/لینک هم باید خالی بماند).
* **بدون تگِ تودرتو**: داخل `<code>`/`<pre>`/`<tg-emoji>` موجود ارتقا
  انجام نمی‌شود.
* **attributeها دست نمی‌خورند**: یک `✅` داخل `href` هرگز تبدیل نمی‌شود.
* **تفکیک چندرباتیه**: فهرست «چت‌های غیرمجاز» به‌تفکیک توکنِ هر ربات
  نگه داشته می‌شود تا یک ربات نمایندگی بدون پریمیوم، ربات اصلی را محدود
  نکند.
* **کلید خاموش فوری**: با `PREMIUM_EMOJI_ENABLED=false` کل لایه دقیقاً مثل
  کلاس‌های والد PTB رفتار می‌کند.
